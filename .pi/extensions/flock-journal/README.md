# flock-journal

Pi extension registering the `flock_event` tool: a durable, append-only
workflow event journal for Flock operator and worker runs.

Each call appends one validated JSON event per line to
`<cwd>/.flock/events.jsonl` (the directory is created if missing). `.flock/`
is gitignored and never committed, the same convention as handoff files.

## Event schema (v1, additive-only)

```json
{"v": 1, "ts": "<ISO-8601, tool-generated>", "run_id": "...", "workflow": "operator-run", "event": "run_started", "repo": "owner/repo", "issue": 45, "pr": 12, "branch": "...", "data": {}}
```

- Required: `run_id`, `workflow`, `event`, `repo`. `ts` and `v` are generated by the tool.
- Known events: `run_started`, `issue_dispatched`, `pr_opened`, `gate_result`, `review_verdict`, `rework_dispatched`, `run_stopped`, `merge_verified`, `issue_closed`, `worktree_cleaned`.
- Optional: `issue`, `pr`, `branch`, `data` (object — e.g. `{passed: true}` for `gate_result`, `{verdict: "clean"|"blocking"}` for `review_verdict`, `{reason: "<verbatim stop reason>"}` for `run_stopped`, pane/workspace/worktree IDs for `issue_dispatched`).

## Contracts

- Validation: missing required fields or unknown event names are rejected with a clear tool error so callers learn immediately.
- Fail-open: a filesystem write failure returns a warning in the tool result and never throws or fails the caller's run.
- Supervisor-only: nested Herdr workers never write journal events; their worktrees are removed after merge.
- Observational: a journal failure never changes workflow behavior, safety stops, approval, merge, or retry policy.
